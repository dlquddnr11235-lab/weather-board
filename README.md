# 현장 일정 날씨판

오늘 현장 일정과 지역별 날씨를 한 화면에서 보고, 날씨 때문에 주의 · 중지를 검토할 일정을 표시합니다. (교육용 가상 데이터)

## 여는 법
- 인터넷 : Vercel 등의 배포 주소로 엽니다. (배포 후 주소를 여기에 적기)
- 내 PC : `index.html`을 더블클릭해 열 수 있습니다. Supabase와 날씨 API, 외부 스크립트를 읽으려면 인터넷 연결이 필요합니다.

## Supabase 일정 데이터 (F-06)
1. Supabase 프로젝트의 SQL Editor에서 [setup.sql](setup.sql)을 직접 실행합니다. 새 `public.wx_tasks` 테이블, DB 제약, RLS 정책, 기본 가상 일정 6건을 만듭니다. 이미 테이블이 있으면 중단하며 기존 데이터를 지우지 않습니다. 같은 초기화 SQL을 반복 실행하지 않습니다.
2. 프로젝트의 Connect 또는 API 설정에서 프로젝트 URL과 공개용 publishable 키를 확인하고 `config.js`의 빈 문자열 두 곳에 넣습니다. 기존 공개용 anon 키도 지원합니다. 비밀 키(`sb_secret_...`, `service_role`)는 사용하지 않습니다.
3. 배포 주소 또는 `index.html`을 열고 목록 조회와 일정 추가를 확인합니다. `config.js`와 `setup.sql`도 함께 배포합니다. 외부 JavaScript는 `supabase-js` 한 개만 사용합니다.

```js
const SUPABASE_URL = 'https://YOUR_PROJECT.supabase.co';
const SUPABASE_PUBLIC_KEY = '공개용 publishable 또는 anon 키';
```

- 일정은 `wx_tasks`에서 ID 오름차순으로 읽습니다. 화면에서 추가하면 DB 저장 성공 후 목록 맨 아래에 표시합니다. 같은 프로젝트에 연결된 다른 브라우저에서는 새로고침하면 보입니다.
- 일정 저장소는 DB 하나입니다. 이전 `data/tasks.json`이나 브라우저 `wx_added`를 읽거나 자동 이관하지 않습니다. 기존 브라우저 저장값을 삭제하지는 않습니다.
- 설정 누락, 스크립트 로딩 실패, 조회 실패 시 화면에 안내하고 일정 추가를 비활성화합니다. 저장 중에는 중복 제출을 막으며 실패 시 입력을 유지합니다. 저장 결과가 불확실하면 새로고침으로 확인한 후 다시 추가하세요.
- DB에서 지역은 세종·대전·태안·보령, 구분은 야외·고소·실내만 허용합니다. 일정 이름과 담당도 NULL·빈 문자열을 허용하지 않습니다.
- 로그인 없는 교육용 가상 데이터이므로 공개용 키로 누구나 조회·추가할 수 있습니다. 공개 역할에는 수정·삭제 권한이 없습니다. [Supabase 공개 키와 RLS 안내](https://supabase.com/docs/guides/getting-started/api-keys)에 따른 구성입니다.

## 오늘 날씨 (F-04)
- 세종 · 대전 · 태안 · 보령의 대표 좌표로 Open-Meteo API를 호출합니다. 키는 필요 없으며 인터넷 연결이 필요합니다.
- 한국 시간(Asia/Seoul)의 오늘 하루 최고 기온, 최대 풍속(m/s), 최대 강수확률을 일정 판단에 사용합니다. 일정 표의 날씨 칸에는 현재 기온·풍속·기준 시각을 표시합니다. 지역별 실제 예보가 같으면 숫자가 같을 수 있습니다.
- API 주소 생성과 응답 해석은 `logic.js`, 호출과 화면 반영은 `app.js`가 맡습니다.
- 일정은 API 응답을 기다리지 않고 먼저 표시합니다. 현재 날씨가 오기 전에는 `날씨 확인 전`, 한 번도 받지 못한 채 실패하거나 10초를 넘긴 지역은 `날씨 수신 실패`로 표시합니다. 이때 판단은 `날씨 확인 전`이며, 실내는 날씨 수신 여부와 관계없이 `영향 없음`입니다.
- 판단은 실내 → 고소 강풍(10m/s 이상) → 폭염(33℃ 이상) → 우천(60% 이상) → 진행 순서로 하나만 표시합니다.
- API 항목과 단위는 [Open-Meteo 공식 문서](https://open-meteo.com/en/docs)를 따릅니다.

## 현재 날씨 자동 갱신
- 상단과 오늘 일정 표의 날씨 칸에 세종 · 대전 · 태안 · 보령의 현재 기온(℃)과 풍속(m/s)을 표시합니다. 일정 표의 기준 시각은 상단과 동일한 한국 시간입니다. API 키나 `weather` 환경 변수는 필요하지 않습니다.
- 페이지를 열 때와 이후 1시간마다 현재 날씨와 오늘 예보를 함께 요청합니다. 진행 중인 요청이 있으면 중복 요청을 건너뜁니다. 브라우저가 비활성 탭의 타이머를 제한하면 갱신이 늦어질 수 있습니다.
- 지역별 API 기준 시각과 실제 수신 시각은 한국 시간으로 표시합니다. [Open-Meteo 현재 날씨](https://open-meteo.com/en/docs)는 기상 모델 기반 값이므로, 1시간마다 요청해도 기준 시각이나 수치가 같을 수 있습니다.
- 갱신 실패 시 현재 날씨에는 이전 값과 수신 시각을 유지하고 `갱신 실패 (이전 값)`을 표시합니다. 한 번도 받지 못했으면 `날씨 수신 실패`로 표시합니다. 해당 지역의 일정 판단은 `날씨 확인 전`으로 돌아갑니다(실내 제외). 다음 갱신 성공 시 정상 표시됩니다.
- 일정 판단은 계속 오늘 하루 최댓값을 사용합니다. `?test=wind`는 일정 판단용 최대 풍속만 12m/s로 바꾸며 상단과 일정 표의 현재 풍속은 API 값을 표시합니다.

## 확인 방법
‘오늘 판단 md로 저장’을 누르면 클릭한 시점의 일정 표 6개 열을 `현장일정_판단_YYYY-MM-DD.md`로 내려받습니다. 파일명 날짜는 한국 시간 기준입니다. 날씨 칸의 현재 기온·풍속·기준 시각, 갱신 실패 시 이전 값 안내, 화면에서 추가한 일정과 판단을 그대로 포함하고, 파일 맨 아래에 교육용 판단 기준 한 줄을 넣습니다. 마크다운 생성은 `logic.js`, 다운로드는 `app.js`가 담당합니다.

| 번호 | 절차와 기대 결과 |
|---|---|
| T-01 | SQL 실행과 연결 설정 후 페이지를 열면 DB의 기본 가상 일정 6건이 보입니다. 추가된 DB 일정은 함께 표시됩니다. |
| T-02 | 가상 일정을 추가하면 맨 아래에 보이고 새로고침해도 남습니다. 날씨가 수신된 지역은 새 일정에도 바로 반영됩니다. |
| T-03 | 인터넷에 연결해 열면 일정 표의 날씨 칸에 지역별 현재 기온 · 풍속 · 기준 시각이 나타납니다. 같은 지역은 상단과 같은 값을 사용하며 판단은 오늘 예보 기준입니다. |
| T-04 | 브라우저 주소의 `index.html` 뒤에 `?test=wind`를 붙여 엽니다. 날씨 수신 후 풍속이 12m/s가 되고 기본 고소 일정 2건이 `중지 검토 (강풍)`로 표시됩니다. 시험 안내도 보입니다. |
| T-05 | 배포 주소에서 상단에 지역 4곳의 현재 기온 · 풍속 · 기준 시각 · 수신 시각이 표시되는지 확인합니다. 탭을 열어 둔 채 1시간 후 수신 시각이 갱신되는지 확인합니다. |
| T-06 | 날씨 수신 후 Open-Meteo 요청을 차단하고 다음 갱신을 기다립니다. 이전 값과 `갱신 실패 (이전 값)` 안내, 실외 일정의 `날씨 확인 전`을 확인합니다. 차단 해제 후 다음 갱신에서 정상 복구되는지 확인합니다. |
| T-07 | ‘오늘 판단 md로 저장’을 눌러 파일명 날짜, 표의 일정 · 지역 · 구분 · 담당 · 날씨 · 판단이 화면과 같은지, 마지막 줄에 판단 기준이 있는지 확인합니다. 일정을 추가하거나 `?test=wind`로 연 뒤 저장해도 현재 표의 결과가 반영되어야 합니다. |
| T-08 | 일정 이름에 세로줄(\|) · 꺾쇠(< >) 같은 문자를 넣고 저장합니다. 마크다운 뷰어에서 열이 어긋나거나 입력 글자가 HTML로 해석되지 않는지 확인합니다. |
| T-09 | 한 브라우저에서 가상 일정을 추가하고 다른 브라우저에서 같은 배포 주소를 새로고침합니다. 같은 일정이 보이고 Supabase `wx_tasks`에도 한 건이 추가되었는지 확인합니다. |
| T-10 | SQL Editor에서 아래의 잘못된 지역·구분 INSERT를 각각 실행하면 CHECK 제약 오류가 발생하고 행이 추가되지 않아야 합니다. |
| T-11 | `config.js`를 빈 값으로 둔 경우 설정 안내, 인터넷 요청 차단 시 조회·저장 실패 안내를 확인합니다. 실패 시 입력과 기존 표는 유지되어야 합니다. |
| T-12 | 일정 표의 현재 날씨가 상단의 해당 지역 값과 같은지 확인합니다. 날씨 수신 후 요청을 차단하고 다음 갱신을 기다리면 표에도 `갱신 실패 (이전 값)`이 표시되어야 합니다. 이 상태에서 md로 저장해 같은 안내가 포함되는지 확인합니다. |

T-10용 쿼리는 각각 따로 실행합니다. 모두 가상 데이터이며 실패하는 것이 정상입니다.

```sql
insert into public.wx_tasks (title, region, kind, owner)
values ('가상 제약 시험', '서울', '야외', '가상담당');
```

```sql
insert into public.wx_tasks (title, region, kind, owner)
values ('가상 제약 시험', '세종', '미허용', '가상담당');
```

추가 실패 확인: 개발자 도구의 요청 차단으로 Open-Meteo 요청만 차단하고 새로고침합니다. DB 일정 목록과 일정 추가는 계속 사용할 수 있고, 실외 일정은 `날씨 확인 전`, 실내는 `영향 없음`으로 표시됩니다. 일부 지역만 실패하면 성공한 지역의 날씨는 계속 표시됩니다.

강풍 시험은 정상 수신한 날씨의 풍속만 바꿉니다. API 실패 시 가짜 기온이나 강수확률을 만들지 않으므로, T-04 확인에는 날씨 수신이 필요합니다. 시험을 마치면 주소에서 `?test=wind`를 지우고 다시 엽니다.
